# FDE (Forward Deployed Engineer / Solutions Engineer) 角色策略

> **注意**：此策略與 `data/fde-technical-positioning.md`（2026-08-16 更新）協同工作。該文件包含 FDE 專門的技術重新定位、硬邊界、自檢加項目。本策略文件提供 resume + coverletter 的生成指導，與 fde-technical-positioning.md 互補。

## 適用角色
Forward Deployed Engineer, Solutions Engineer, Implementation Engineer, Field Engineer, Deployment Engineer, Customer Engineer, Technical Account Manager, Professional Services Engineer, Deployment Engineer, Solutions Architect, Pre-Sales Engineer, Post-Sales Engineer, Field Solutions Engineer, Customer Success Engineer, Technical Consultant, Solutions Consulting, Technical Services, Field Services, Deployment Services, Implementation Services

## 核心特點
FDE/Solutions Engineer 角色的核心是技術實施、客戶嵌入式系統構建、API/集成工作、數據管道、自動化/工作流工程，以及將客戶需求轉化爲具體的技術解決方案。這些角色需要技術能力（SQL、系統集成、API 集成、自動化）和客戶導向（嵌入客戶環境、理解客戶需求、快速交付解決方案）的結合。

## 核心原則（來自 fde-technical-positioning.md）

### 真實技術表面區域（不要編造 CS 學位或 SWE 背景）
- PicoPilot AI：ML-driven workflow，與 Data Science/Engineering 合作
- Attribution pipeline：Segment + Rockerbox + BigQuery + SQL 的多系統集成
- Agentic bid optimization：生產環境中的自動化決策系統配置/運營
- SQL：每個角色都用過（Alibaba、Next2Market）
- Alipay B2B wallet：API 集成，跨境合規
- WeWork Labs：嵌入 18+ 投資組合公司的系統（CRM、數據管道）——這是 FDE 動作的結構性模擬

### 硬邊界（永不聲稱）
- ❌ Computer Science 學位
- ❌ "wrote production code in [language]"（除非實際的 SQL/腳本聲稱已經是真的）
- ❌ 特定編程語言流暢度（Python、Java 等）（除非經歷銀行確實有依據）
- ❌ 建立/發布客戶端軟件產品作爲工程師
- ✅ 正確的定位：**technical operator / implementation & systems generalist**——建立和運行生產自動化和數據系統，有直接的嵌入客戶環境經歷

### FDE 執行摘要模式（來自 fde-technical-positioning.md）

1. **句 1**：以技術/系統操作者 + 客戶嵌入式交付經歷的身份定位——不是"growth marketer"
2. **句 2-3**：PicoPilot AI（ML 驅動系統，與 Eng/DS 合作）+ WeWork Labs 投資組合嵌入（18+ 公司的 0→1 系統構建）——這兩個應該通常錨定執行摘要
3. **句 4**：SQL/數據管道/API 集成流暢度，貫穿整個職業弧線
4. **句 5**：命名目標公司的產品/任務，直接說明爲什麼嵌入式技術實施背景適合他們的 FDE 模式

### FDE 自檢加項目（運行在基礎 Step 8 之上）

1. ✅ 執行摘要是否以技術/系統語言開頭，而非營銷語言？
2. ✅ SQL 是否在整個簡歷中至少被具體提到兩次（不僅僅是"data-driven"）？
3. ✅ WeWork Labs 是否明確繪製了"嵌入客戶/投資組合系統"的平行關係？
4. ✅ 是否有零個沒有經歷銀行依據的編程語言、CS 學位或 SWE 頭銜聲稱？
5. ✅ 簡歷是否避免了將"營銷"作爲主要自我描述出現在執行摘要或職位頭銜的任何地方？（FDE 應用中，頭銜應該讀作 Systems/Technical/Program，而非 Marketing/Growth）

## Bullet 重點指導（技術系統重新定位）

每條 bullet 必須對應 FDE 核心職能的一個環節，並通過技術系統的角度重新定位：

### 客戶嵌入式實施/現場部署（Customer-Embedded Implementation）
- **重新定位**：WeWork Labs 諮詢 → 嵌入 18+ 投資組合公司的系統，從 0→1 構建和修復 CRM 和數據管道
- **強調**：嵌入客戶環境、理解客戶數據/系統、快速構建有效解決方案、移動到下一個客戶
- **例子**：在 WeWork Labs，嵌入在 18+ 投資組合公司的系統（CRM、數據管道）中，從 0→1 構建和修復他們的 GTM 基礎設施——這與 FDE"嵌入客戶，構建他們需要的東西，然後移至下一個"的動作完全一致

### 技術解決方案設計/系統設計（Technical Solutioning & Systems Design）
- **重新定位**：Alibaba attribution stack → 多系統歸因和數據管道設計，將 5 個以上 ad platform 統一到單一測量層
- **強調**：系統架構、數據流設計、集成設計、可擴展性
- **例子**：設計了多系統歸因和數據管道（Segment + Rockerbox + BigQuery + SQL），將 5 個以上 ad platform 統一到單一測量層——這是實實在在的系統集成工作，解決了數據孤島問題

### API/集成工作（API & Integration Work）
- **重新定位**：Alipay B2B wallet → API 集成，跨境合規，部署到 5M+ 賬戶
- **強調**：API 設計/集成、跨系統數據流、第三方集成、合規考慮
- **例子**：將 Alipay B2B 錢包集成部署到 5M+ US SMB 賬戶，涉及跨境合規和技術集成——這不是僅僅一個業務交易，而是一個真正的 API 集成項目

### SQL/數據管道（SQL & Data Pipelines）
- **重新定位**：Alibaba/N2M SQL → 數據管道、儀表板、cohort 模型、預測
- **強調**：SQL 具體技能、數據管道構建、數據提取/轉換/加載、數據模型設計
- **例子**：使用 SQL 構建了 dashboards、cohort models 和 forecasting 模型，支撐了每一個重大決策——這是真實的數據工作，而非"與數據團隊合作"

### 自動化/工作流工程（Automation & Workflow Engineering）
- **重新定位**：Alibaba agentic bid optimization → 生產環境中的自動化決策系統配置/運營
- **強調**：自動化系統配置、工作流設計、實時數據反饋循環、系統運營
- **例子**：配置和運營了 agentic 出價優化和即時創意輪換系統——這是在生產環境中運行的自動化決策系統，帶有實時數據反饋循環

### 與 Engineering/Data Science 的跨職能合作（Cross-Functional with Eng/DS）
- **重新定位**：PicoPilot AI build → 直接與 Data Science 和 Engineering 合作構建 ML-driven 系統
- **強調**：技術合作、系統聯調、共同解決技術問題、而非僅僅提交需求
- **例子**：PicoPilot AI 項目是直接與 Data Science 和 Engineering 合作構建的，而非僅僅提交需求——這展示了跨職能技術合作的能力

### 將客戶需求轉化爲技術解決方案（Translating Customer Needs to Technical Solutions）
- **重新定位**：Starbucks WeChat+CRM pipeline → 將線下購買行為連接到線上個性化系統的數據工程/系統集成交付
- **強調**：理解客戶需求、設計技術解決方案、實施集成、交付結果
- **例子**：Starbucks 的 O2O 數字化轉型：WeChat + CRM 數據管道，將線下購買行為連接到線上個性化系統——這是真正的數據工程/系統集成交付，而非僅僅"諮詢"，實現了 20% LTV 提升

### 生產系統所有權（Production Systems Ownership）
- **重新定位**：Alibaba AI Performance Stack → 生產環境中系統的日常運營、監控、優化
- **強調**：生產系統運營、性能監控、故障排除、持續改進
- **例子**：管理了 $12M+ 年度預算的全棧 AI-native 性能營銷引擎，負責生產環境中系統的日常運營

### 客戶端技術信任建立（Client-Facing Technical Trust-Building）
- **重新定位**：Next2Market 企業客戶 → 技術 + 關係的結合
- **強調**：與客戶技術團隊的溝通、技術建議的可信度、關係建立
- **例子**：爲 Samsung、Anker、Adidas DTC、Columbia Sportswear、Insta360 等企業客戶提供技術 + 關係綜合服務

### 跨組織拓展技術流程（Scaling Technical Process Across Org）
- **重新定位**：Alibaba org build → Pods 接受數據/自動化工具培訓
- **強調**：技術流程推廣、工具培訓、技術能力建設
- **例子**：從 3 個 pod 擴展到 10+，建立了 OKR 框架、pod-level KPIs 和每週性能/創意審查節奏，確保每個 pod 都能有效使用數據和自動化工具

### 現場系統的快速問題診斷（Fast Problem Diagnosis in Live Systems）
- **重新定位**：Alibaba/N2M root-cause 診斷 → 快速識別問題根因、實施修復
- **強調**：問題診斷、根因分析、快速修復、防止複發
- **例子**：在 CAC payback 和 churn model 工作中，進行 root-cause 診斷並實施可測量的修復，解決了跨渠道歸因混淆的問題
