# 自动化职位筛选 + 对应性简历生成工作流

## 触发条件
- 用户提供一批公司/职位来源（列表、文件、ATS 查询结果、或从 job-sources.json 选出的子集）
- 用户指定区域/地点过滤（如只保留纽约、湾区、远程等）
- 用户允许按优先级自动选可投职位（例如公司最多 2 个、排除名单、去重、按发布时间或匹配度排序）
- 目标是为入选职位各自生成一份“JD 核心要求 → 经验库对应项目”映射明确的简历

## 输入
- 职位来源：公司 slug / ATS 类型 / 职位 ID / 标题 / 链接 / 发布日期，可来自多种格式
- 区域过滤规则：接受/拒绝的地点模式
-  exclusions: 不投的公司、已投记录（应用账本/ledger）、公司上限
- 经验库文件: `data/barron-experience-bank.md`（固定事实、指标、日期）
- JD 来源：每个入选职位的完整职位描述文本或可抓取链接
- 可选模板/输出路径偏好

## 处理流程

### 1) 净化与过滤职位清单
- 读取输入清单，统一字段（公司、ATS 类型、职位 ID、标题、链接、发布日期、位置）
- 应用区域过滤：只保留通过地点规则的职位
- 应用排除规则：去掉 exclusion 公司、去掉已投记录中匹配的公司+职位，应用公司数量上限
- 去重：按公司+标题稳健去重
- 按优先级排序：综合发布时间、匹配关键词强度、ATS 可访问性等，输出有序候选列表
- 输出中间结果：filtered candidate list，附带每个职位的入选理由/过滤原因

### 2) 抽样与结构化 JD 获取
- 对候选列表，获取每项职位的完整 JD 文本（已有文本则直接用，链接则抓取并提纯）
- JD 文本提纯：移除页脚/法律声明/申请流程提示等 boilerplate，保留职位要求、职责、资格、公司介绍中与匹配相关的部分
- 记录 JD 获取方式/时间，便于后续重跑

### 3) JD 核心要求提取
- 对每个 JD，提取结构化要求表：
  - 要求/关键词
  - 优先级（must-have / nice-to-have）
  - 最佳匹配的经验库项目
  - 要前置的指标
- 必须识别：名词工具/平台/指标、职责短语、资格门槛、 seniority 信号、角色隐含的关键结果指标
- 要求表中任何一行若没有匹配项目，标记为缺口，后续处理

### 4) 经验库映射与策略选择
- 用经验库+角色分类规则判断该 JD 属于的角色类型（Growth / Marketing(PMM/GTM) / Sales-RevOps / Operations / FDE / General）
- 加载该角色对应的策略：标题适配、摘要锚、 bullet 侧重、关键词优先级、自查清单
- 对每条 must-have 要求，确认映射到的具体项目和指标；若无自然匹配，视情况重构相邻项目或标记为需人工确认的缺口

### 5) 对应性简历生成
- 为每个入选职位生成一份简历 JSON，要求：
  - 每条 bullet 对应某一具体 JD 要求行
  - 出现 must-have 关键词的覆盖
  - 角色适配标题、完整5段经历（含 GSV 3条底线）、不写 Core Competencies 区块
  - 包含强制自查通过记录
- 如有必要，输出时附带“关联说明”：哪条经历回答了哪条 JD 要求

### 6) 输出与交付
- 每个职位输出独立简历文件（.docx 或用户指定格式）
- 附带每份简历的“JD 要求 → 经历映射”说明（可作为元数据或单独小节）
- 汇总表：候选职位、入选/排除原因、匹配度、输出文件路径、待处理缺口

## 输出物
- 筛选后职位候选清单（含过滤原因）
- 每个入选职位的：
  - JD 核心要求表
  - 对应的针对性简历（含 JD-requirement 映射）
  - 若有必要：cover letter（按相同角色策略生成）
- 汇总交付包：列表、映射说明、输出文件路径、待确认缺口

## 验收 / 止步条件
- 筛选结果可解释：每个入选/排除项都有原因
- 每个入选职位都有完整且可回查的 JD 要求表
- 简历 bullet 能对应到具体 JD 要求，不出现“为凑数”的空泛条目
- 经验库事实不被篡改：日期、公司名、核心指标固定；不在 GSV/WeWork 预2018部分使用后起工具名称
- 自查未通过时不交付：例如缺少 GSV 3条、must-have 关键词未覆盖、出现禁用动词、薄到不满一页等
- 对于无法自动解决的缺口，标记为人工确认而不是静默编造

## 注意事项
- 此工作流不替代最终人工审阅；若用户要求“直接投”，还需叠加申请渠道/提交步骤及验证
- JD 抓取可能因页面结构/反爬而失败，失败项要记录并可跳过或降级为手输 JD
- 角色分类是启发式；混淆时可输出多个候选分类供后续确认，不要硬选一个导致错配
- 如果用户给的是小清单/个职位，可只跑单职位分支，不必强走批量流程
